3. FINDINGS & AUDIT CONCLUSION
------------------------------------------------------------------------------------
Confirmed Audit Facts:
  1. In scripts/run_hardware.py (lines 98 and 100), the calls to mapper_esp for
     'esp_no_thermal' and 'esp_thermal' are completely IDENTICAL:
       Line 98:  mapper_esp(b_circ, target, temps_mk=None, use_thermal=False, exhaustive=False)
       Line 100: mapper_esp(b_circ, target, temps_mk=None, use_thermal=False, exhaustive=False)
  2. Neither call passes 'p1'. Both explicitly pass 'use_thermal=False'.
  3. Consequently, the hardware 'esp_thermal' arm never applied any thermal penalty term.
     The identical layouts, depths, gate counts, and measured metrics between 'esp_thermal'
     and 'esp_no_thermal' in runtime_table.csv are produced entirely by code identity,
     NOT because the layout mapper actively evaluated thermal data and selected identical layouts.
  4. The previous README explanation ('Shared circuit => thermal == ESP by construction ...
     because measured P(1|0) remained near or below readout error') was misleading.
  5. Conclusion: Hardware execution on ibm_marrakesh provides NO empirical evidence regarding
     the thermal term. Evidence for the thermal term is simulation-only (and subject to the
     existing circularity caveat).
